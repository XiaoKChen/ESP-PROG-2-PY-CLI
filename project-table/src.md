### esp_prog2_flasher/
- **Responsibility:** Implements the flasher engine, its two entry points (TUI/CLI), and the frozen DFU config-block encoder.
- **Key files:** `flasher.py`, `dfu_config.py`, `cli.py`, `app.py`
- **Relationships:** imports from: `pyocd` (target flash), `esptool` (probe flash), `pyserial` (port detection), `truststore` (TLS), `textual` (TUI widgets) — exposes: `flasher.detect`, `flasher.flash`, `flasher.flash_probe`, `flasher.write_dfu_config`, `dfu_config.build_config_block`, `dfu_config.boot_ids_for_device`, `cli.main`, `app.run`/`app.FlasherApp`

- **`__init__.py`** — package marker; defines `__version__ = "1.0.0"`, imported by `app.py` for the TUI subtitle.
- **`__main__.py`** — enables `python -m esp_prog2_flasher`; delegates directly to `cli.main()`.
- **`cli.py`** — argparse entry point (`main()`); bare invocation launches the TUI (`app.run`), flags drive `flasher` headlessly (`--list`, `--detect`, `--flash`, `--flash-probe`, `--update-probe-fw`). Adds `--manufacturer`/`--product` (product now names a KNOWN device from `DEVICE_NAMES` or any CUSTOM string) and the `--boot-cmd-id`/`--boot-reply-id` CAN ID flags (parsed by `_can_id`, resolved together with the device via `_resolve_dfu_config`/`_prompt_dfu_config`/`_prompt_boot_ids`); also intercepts the hidden `ESPTOOL_SHIM_FLAG` used by frozen builds to dispatch to `esptool.main()` in-process.
- **`app.py`** — Textual TUI (`FlasherApp`), `HexPickerScreen` modal file browser, and `_HexDirectoryTree`. Calls `flasher` from `@work(thread=True)` background workers, never touching USB/serial directly. Device selection is a `Select` populated from `DEVICE_NAMES` plus a `"Custom…"` sentinel (`CUSTOM_DEVICE_VALUE`/`CUSTOM_DEVICE_LABEL`) that reveals a custom-name `Input` and unlocks editable boot-CAN-ID inputs (`on_select_changed` locks/fills them from `DEVICE_CAN_IDS` for KNOWN devices); `_parse_can_id` validates the ID inputs before flashing.
- **`dfu_config.py`** — encodes the frozen v2 (80-byte) DFU config block written to RA4M1 data flash at `0x40101C00`: magic/version/lengths header, 32-byte manufacturer + 32-byte product ASCII fields, a 4-byte boot CAN ID pair (`boot_cmd_id`/`boot_reply_id`, `0xFFFF` sentinel = unset), and a trailing CRC32 over the first 76 bytes. `DEVICE_CAN_IDS` is the single source of truth mapping known device names (ODU/IDU controller, superheat, air sensor, power board, radar, articulation) to fixed `(boot_cmd_id, boot_reply_id)` pairs mirroring `airform-server-dev`'s BOARDS table; `DEVICE_NAMES` is derived from its keys. Exposes `build_config_block()`, `boot_ids_for_device()`, validation helpers, and error types `DfuConfigError`, `InvalidNameError`, `InvalidCanIdError`.
- **`flasher.py`** — UI-agnostic core wrapping pyOCD (probe detection via VID `0x303A`/PID `0x1002`, `detect()`/`flash()`/`write_dfu_config()` against target `r7fa4m1ab`, `_program_config_block()` writing/verifying the DFU block via `FlashLoader` with the RA4M1 `DFLCTL` data-flash read-enable quirk) and esptool (`flash_probe()`, `download_probe_firmware()`, `find_probe_serial()`/`find_probe_firmware()`). `flash()` accepts and forwards `boot_cmd_id`/`boot_reply_id` through `_config_block_or_none()` to `dfu_config.build_config_block()`. Bundled `hex/`/`firmware/` assets are resolved via `_find_bundled()` (PyInstaller `_MEIPASS` first, then walking up from package/CWD). Defines `FlasherError`, `ProbeNotFoundError`, `FlashFailedError`, `TargetState`, `DetectResult`, `ProbeInfo`, `ProbeSerial`.
