- **dfu_config.py** — encodes the frozen 76-byte DFU manufacturer/product config block (`build_config_block`) with magic/version/lengths/CRC32 per a documented little-endian layout; validates names via `_validate_name` (printable ASCII, ≤32 chars) raising `InvalidNameError`; defines `CONFIG_ADDRESS` (RA4M1 data flash `0x40101C00`), `DATA_FLASH_ENABLE_ADDR`, and the provisioning presets `DEFAULT_MANUFACTURER = "Normal Corporation"` and `DEVICE_NAMES` (ODU Controller, ODU Superheat, ODU Air Sensor, ODU Power Board, IDU Controller, IDU Power Board, IDU Radar, IDU Articulation, IDU Air Sensor). Contract mirrors the bootloader's `src/boot/dfu_config.*`.
- **flasher.py** — UI-agnostic core. Probe layer: `list_probes`, `find_esp_prog`, `_choose_raw`/`_raw_probes` (lazy `pyocd.core.helpers.ConnectHelper`) identify the ESP-Prog-2 by VID `0x303A`/PID `0x1002`. Target layer: `detect` opens a pyOCD `Session` against target type `r7fa4m1ab`, halts, and reads PC to classify `TargetState` (`NO_PROBE`/`NO_TARGET`/`CONNECTED`/`CONNECTED_BLANK`) into a `DetectResult`; `flash` reset-and-halts, runs `pyocd.flash.file_programmer.FileProgrammer.program`, optionally writes the DFU block via `_program_config_block`/`FlashLoader` (toggling `DATA_FLASH_ENABLE_ADDR` before read-back verify), then resets; `write_dfu_config` does the config-block write standalone. Probe-firmware layer: `find_probe_firmware`/`find_default_hex` resolve bundled `firmware/esp-prog2.bin` / `hex/dfu_minima.hex` via `_find_bundled` (PyInstaller `_MEIPASS` first, else walk-up search); `find_probe_serial` (pyserial) distinguishes ROM download mode vs. running bridge by PID; `download_probe_firmware` fetches Espressif's official JTAG image over `truststore`-backed HTTPS as a separate reference file; `flash_probe` shells out to `esptool` (or re-execs itself with `ESPTOOL_SHIM_FLAG` when frozen), streaming percent-progress and log lines. Defines errors `FlasherError`/`ProbeNotFoundError`/`FlashFailedError` and dataclasses `ProbeInfo`, `DetectResult`, `ProbeSerial`. Backends imported lazily so module import never triggers USB/network I/O.
