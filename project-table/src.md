## src/esp_prog2_flasher/

- **Responsibility:** The package: `flasher.py` is the hardware engine (no Textual dependency); `dfu_config.py` and `board_profile.py` encode and decode the frozen on-device blocks; `cli.py` is the headless entry point; `app.py` owns the TUI session.
- **Key files:** `flasher.py`, `cli.py`, `app.py`, `dfu_config.py`, `board_profile.py`
- **Relationships:** imports from: `dfu_config` ← `board_profile` ← `flasher` ← `cli` / `app`; only `app.py` imports `tui/`. Exposes: `flasher.*` (flash/detect/provision/read/SOLO functions), `cli.main`, `FlasherApp`, `run`.

- **`__init__.py`** — Package marker; `__version__ = "3.2.0"`, shown in the TUI header.
- **`__main__.py`** — `python -m esp_prog2_flasher` calls `cli.main()`; also the script PyInstaller freezes.
- **`dfu_config.py`** — The 80-byte v2 DFU config block (USB manufacturer/product names, optional boot CAN ID pair): `build_config_block`, and `parse_config_block`, which never raises and also accepts a legacy v1 block. Frozen contract with the bootloader. Owns `CONFIG_ADDRESS` and `DEVICE_CAN_IDS`, the single source of truth for known devices (incl. `SOLO ODU Controller` 0x05/0x06, `SOLO IDU Controller` 0x07/0x08); `DEVICE_NAMES` derives from it. Raises `InvalidNameError` / `InvalidCanIdError`.
- **`board_profile.py`** — The ESP32-S3 board-profile record at cancfg offset 0x50, in two versions; frozen contract with the Embedded-CAN-Bootloaders firmware.
  - **v1 (24 bytes):** TWAI pins, `Bitrate`, hold-LOW mask. **v2 (56 bytes):** adds `hold_high_mask` and `I2cSafeWrites` (SDA, SCL, addr7, up to 8 reg/value pairs; `NO_I2C` = 0xFF). Only `c-cpp-esp32-v1.3.0`+ bundles read v2.
  - `encode_profile_record(record, version)` refuses a v1 encoding that would drop v2-only fields; `profile_record_version` reports a valid record's version; `parse_profile_record` reads either version and never raises.
  - `build_cancfg_image(block, record, version)` pads block + record to the 4 KB cancfg image. Owns `SOLO_PROFILES` (ODU preset with safe holds and EMC2305 fan-off writes, plus `BoardProfile.v1_record` / `record_for(version)`; IDU preset identical in both versions) and `DEFAULT_PROFILE_RECORD`.
  - `describe_profile_record` / `describe_read_profile` give the one-line text used by the CLI and TUI.
- **`flasher.py`** — UI-agnostic engine; all backends imported lazily.
  - pyOCD over SWD: RA4M1 hex, application `.bin` and DFU config block; PSoC 6 main flash via `psoc6_flash_segments` / `flash_psoc6`; `detect` / `detect_psoc6`.
  - Node download mode: `_enter_node_download_mode` checks the chosen port once before any esptool call. A USB serial that is a bare 12-hex-digit MAC (running app/updater) gets a 1200-baud touch (`_touch_1200_baud`, `NODE_TOUCH_BAUD`) and is followed by that MAC only to the 303A:1001 ROM port whose serial is the same MAC with colons, polling for up to `NODE_ROM_PORT_TIMEOUT_S` (10 s) every `NODE_ROM_PORT_POLL_S` (0.5 s). A ROM port that never appears raises `FlashFailedError` with the hold-BOOT hint before esptool runs. Any other port is used as given.
  - Node config: `provision_node` and `read_node_config` (returns `NodeConfig(config, profile)` from one read) both take `runner` and `enter_download_mode` seams. Every esptool step runs with `--after no-reset`; a final `_reboot_node_board` call (`chip-id` with `--after watchdog-reset`, exit code ignored) reboots the board. The cancfg offset comes from the node's partition table (`_node_cancfg_offset`).
  - esptool: ESP-Prog-2 firmware (`flash_probe`, `download_probe_firmware`); SOLO bundles (`load_solo_bundle`, `fetch_solo_bundle` via `gh`, `flash_solo`, which also takes `runner` and `enter_download_mode` seams and ends with the same watchdog-reset reboot).
  - Probe-port detection: `SerialPortInfo` (with `serial_number`, the USB serial or None, filled by `list_serial_ports`) with `is_esp_prog_bridge` (303A:1002, the running bridge) and `is_download_mode_candidate` (303A:1001, the ESP-Prog-2 in download mode or a SOLO board). `find_probe_serial()` returns only the bridge and never guesses; `find_download_mode_candidates()` lists the 1001 ports.
  - SOLO record gate: `DEFAULT_SOLO_BUNDLE_TAG` = `c-cpp-esp32-v1.3.0`, `PROFILE_V2_MIN_BUNDLE_VERSION` (1, 3, 0), `bundle_profile_version`, `read_bundle_version`, `release_tag_profile_version`. `flash_solo` writes v2 when the bundle reads it, else the preset's v1 record with a warning; `provision_node` writes v2 only if the node already holds a valid v2 record.
  - Owns the `FlasherError` hierarchy (`ProbeNotFoundError`, `FlashFailedError`, `BundleError`), `ESPTOOL_SHIM_FLAG`, bundled-asset lookup (PyInstaller `_MEIPASS` first) and cancfg partition-table parsing.
- **`cli.py`** — argparse entry point; with no flags it launches the TUI (imported lazily). Flags drive `flasher` headlessly, including `--flash-solo`, `--provision-node` and `--read-node-config` (prints the config plus the board profile via `describe_read_profile`); intercepts the hidden esptool shim flag.
  - Node and SOLO flags require `--port` and never auto-detect a port; the `--port` help explains the 1200-baud touch and the hold-BOOT fallback for a blank board. `--flash-probe` without `--port` uses only the running bridge; with only 303A:1001 candidates it lists them and exits 2.
  - `--no-state` (TUI only) skips loading and saving remembered state; passed to `app.run`. `--list` reports the running bridge and each download-mode candidate separately.
- **`app.py`** — Textual `FlasherApp`. Owns the session state (`Settings`, detect results, serial port, recents, log, status), command dispatch, and the thread workers that run every flasher call (exclusive `flash` group); never touches hardware directly. Saved state is loaded and written through `tui/state.py`; `/ c` forgets it. `run()` is the module entry point used by `cli.py`.
