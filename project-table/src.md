**src/** — the `esp_prog2_flasher` Python package (3.0.0): the pyOCD/esptool flashing engine, the DFU and SOLO board-profile encoders, the argparse CLI, and the Textual TUI that drives them.

- **Responsibility:** All runtime code. The engine (`flasher.py`) has no UI dependency; `cli.py` and `app.py` are the two front-ends over it.
- **Key files:** `esp_prog2_flasher/cli.py`, `esp_prog2_flasher/app.py`, `esp_prog2_flasher/flasher.py`, `esp_prog2_flasher/dfu_config.py`, `esp_prog2_flasher/board_profile.py`, `esp_prog2_flasher/tui/`
- **Relationships:** `cli.py` imports `flasher`, `board_profile.SOLO_PROFILES`, `dfu_config` and lazily `app.run`. `app.py` imports `flasher`, `board_profile`, `dfu_config` and `tui/`. `flasher.py` imports `dfu_config` (and `board_profile` only for typing/lazily). `board_profile.py` imports `dfu_config`.

## src/esp_prog2_flasher/

- **Responsibility:** The package root: the UI-agnostic flashing engine, the two binary-format encoders (config block, board-profile record), the headless CLI, the TUI host, and the version marker.
- **Key files:** `flasher.py`, `cli.py`, `app.py`, `dfu_config.py`, `board_profile.py`
- **Relationships:** `dfu_config.py` uses the standard library only. `board_profile.py` uses `dfu_config` (`BLOCK_SIZE`, `DEVICE_CAN_IDS`, `build_config_block`). `flasher.py` uses `dfu_config` and `board_profile`. `cli.py` and `app.py` sit on top of all three.

- **`__init__.py`** — Package marker; `__version__ = "3.0.0"`, read by the TUI header.
- **`__main__.py`** — `python -m esp_prog2_flasher` entry; calls `cli.main()`. Also the script PyInstaller freezes.
- **`cli.py`** — argparse entry point. A bare run launches the TUI (`app.run`). Flags drive `flasher` headlessly: `--list`, `--detect` (`--psoc6`), `--flash`, `--flash-psoc6`, `--flash-app` (`--app-address`), `--flash-probe`, `--update-probe-fw`, `--provision-node`, `--read-node-config`, `--flash-solo [odu|idu]` (`--bundle`, `--bundle-tag`, `--app`, `--migrate-stock`), plus `--hex`, `--probe-bin`, `--port`, `--manufacturer`, `--product`, `--boot-cmd-id`, `--boot-reply-id`, `--freq`. Node and SOLO flags require `--port` (never auto-detected). `SOLO_BOARDS` maps `odu`/`idu` to presets. Dispatches the hidden `--esptool-shim` flag for frozen builds.
- **`app.py`** — `FlasherApp` (Textual). Owns session state (`Settings`, RA4M1/PSoC 6 detect results, serial port, recents, log lines), dispatches commands, and runs every job in `@work(thread=True)` workers in exclusive `flash` and `probe` groups. Calls `flasher` only; never touches USB or serial itself.
- **`flasher.py`** — UI-agnostic engine.
  - RA4M1 over pyOCD: `detect`, `flash` (hex plus optional config block), `flash_app` (sector erase at `APP_BASE_ADDRESS` 0x4000), `write_dfu_config`.
  - PSoC 6: `detect_psoc6`, `flash_psoc6` with `psoc6_flash_segments`.
  - ESP-Prog-2 firmware via esptool: `flash_probe`, `download_probe_firmware`, `find_probe_serial`; `list_serial_ports` / `SerialPortInfo` for picking a SOLO board's port.
  - CAN node cancfg via esptool: `provision_node`, `read_node_config`, partition-table parsing.
  - SOLO: `load_solo_bundle`, `fetch_solo_bundle` (GitHub CLI, default tag `c-cpp-esp32-v1.2.1`), `flash_solo` (bootloader, partition table, otadata, updater, cancfg image at 0x11000, read-back, optional `ota_0` app, then a separate watchdog-reset `chip-id` call), `otadata_selecting_ota0`.
  - Errors: `FlasherError`, `ProbeNotFoundError`, `FlashFailedError`, `BundleError`.
- **`dfu_config.py`** — The 80-byte v2 DFU config block: `build_config_block`, `parse_config_block` (also reads v1), `CONFIG_ADDRESS` 0x40101C00. `DEVICE_CAN_IDS` is the single source of truth for known devices and their fixed CAN ID pairs (including `SOLO ODU Controller` 0x05/0x06 and `SOLO IDU Controller` 0x07/0x08); `DEVICE_NAMES` derives from it. Also `DEFAULT_MANUFACTURER` and the `DfuConfigError` hierarchy. Frozen layout shared with the bootloader.
- **`board_profile.py`** — The 24-byte SOLO board-profile record (magic `0xDFB0A7D1`, TWAI tx/rx GPIOs, bitrate code, hold-LOW mask, CRC) at cancfg offset 0x50: `encode_profile_record`, `parse_profile_record`, `build_cancfg_image` (4 KB image: v2 block, record, 0xFF pad). Holds `ProfileRecord`, `BoardProfile`, `Bitrate`, `DEFAULT_PROFILE_RECORD` and `SOLO_PROFILES` (`SOLO ODU Controller` on `node-4MB`, `SOLO IDU Controller` on `idu-16MB`). Frozen contract shared with the ESP32 bootloader and updater.

## src/esp_prog2_flasher/tui/

- **Responsibility:** The TTSSH-style terminal UI introduced in 3.0.0: palette, dashboard, `/` command table, per-target wizards and their job flows, file browser, and framing widgets. It draws state and turns keys into requests; `app.py` owns state and runs jobs.
- **Key files:** `screens.py`, `wizard.py`, `flows.py`, `targets.py`, `commands.py`, `theme.py`
- **Relationships:** `flows.py` imports `flasher`, `board_profile`, `dfu_config`, `browser`, `targets`, `widgets`, `wizard`. `wizard.py` and `browser.py` import `commands`, `screens`, `widgets`. `screens.py` imports `commands`, `targets`, `widgets`. `widgets.py` imports `commands`, `theme`. `commands.py` imports `targets`. `targets.py` imports `board_profile.SOLO_PROFILES`. Only `app.py` imports the package from outside.

- **`__init__.py`** — Docstring only; names the package's modules.
- **`theme.py`** — TTSSH palette as light and dark Textual themes (`THEMES`, `DARK_THEME_NAME`, `LIGHT_THEME_NAME`), `STATUS_SYMBOLS` (✓ ! ✗ ·), `StatusLevel`, and `theme_name_for_terminal` (light only when `COLORFGBG` says so). The only place colours are named.
- **`commands.py`** — The `/` command table, the single source for the popup, the details pane and help: `DASHBOARD_COMMANDS`, `BROWSER_COMMANDS`, `GLOBAL_COMMANDS`, `PRIMARY_ACTIONS` (what Enter does per target kind), `popup_commands`, `help_rows`. `CommandAction` lists every action `app.py` handles.
- **`targets.py`** — Dashboard data: `TARGET_GROUPS` (RA4M1 and PSoC 6 over SWD, one SOLO row per `SOLO_PROFILES` preset, the ESP-Prog-2 over USB), `Target`, `RecentRun`, `Operation`, `MAX_RECENTS` = 10, `relative_time`. Recents are session-only (persistence is issue #19).
- **`widgets.py`** — Framing widgets: header line, status line, footer hints, `FilterList`, `DetailsView`, `ChromeState` (shared state `app.py` updates), `Field`, `GlobalCommand`, `StatusPosted`, spinner frames, `APP_TITLE`.
- **`screens.py`** — `ChromeScreen` frame, `DashboardScreen` (targets and recents left, details and commands right; details hidden below 80 columns), `CommandPopup`, `RunScreen` (running job, progress), `LogScreen`, `HelpScreen`, `NARROW_BREAKPOINTS`.
- **`wizard.py`** — Step-by-step `WizardScreen`: `TextStep`, `ChoiceStep`, `Confirm`, `WizardSpec`, `Answers`, `Choice`, `BROWSE_VALUE`. Dismisses with answers only after the final step (and `y` on a confirm); otherwise `None`.
- **`flows.py`** — Per-target wizards and job types. `Settings` (images, device and names, CAN IDs, SOLO port, bundle, app, migrate flag); jobs `BootFlashJob`, `AppFlashJob`, `Psoc6FlashJob`, `SoloFlashJob`, `SoloProvisionJob`, `SoloReadJob`, `ProbeFlashJob`; flow builders (`boot_flash_flow`, `app_flash_flow`, `psoc6_flash_flow`, `solo_flash_flow`, `solo_provision_flow`, `solo_read_flow`, `probe_flash_flow`, edit flows) and the confirm `summary`. Pure: no hardware calls.
- **`browser.py`** — Filterable file and folder browser (`BrowserScreen`, `BrowseSpec`, `start_folder`, `BrowserMode`). Returns an existing path or `None`; `/` offers `.` (use this folder) and `t` (type a path); lists drives at a Windows drive root.
