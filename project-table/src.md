- **`cli.py`** — argparse entry point (`main()`, console-script target). Bare invocation launches the TUI (`app.run()`); flags dispatch headlessly to `flasher`: `--list`, `--detect`, `--flash` (bootloader `.hex` via `flasher.flash()`), `--flash-app <BIN>` + `--app-address <ADDR>` (application `.bin` via `flasher.flash_app()`, default address `flasher.APP_BASE_ADDRESS`), `--flash-probe`, `--update-probe-fw`, plus DFU-naming flags `--manufacturer`/`--product`/`--boot-cmd-id`/`--boot-reply-id` resolved by `_resolve_dfu_config()`/`_prompt_dfu_config()`/`_prompt_boot_ids()`. - **`app.py`** — Textual TUI (`FlasherApp`, `run()`). Three panels: target (bootloader `.hex` picker, manufacturer/device `Select` with `CUSTOM_DEVICE_VALUE`/`CUSTOM_DEVICE_LABEL`, boot-CAN-ID inputs, Detect/Flash-target), ESP-Prog-2 firmware (Get official/Flash probe), and an "Application (RA4M1 over SWD)" panel (`.bin` picker + "Flash app" button + `a` keybinding → `action_flash_app()`/`flash_app_worker()` → `flasher.flash_app()`). `FilePickerScreen`/`_FilteredDirectoryTree` are suffix-generalized (`suffix_filter`) and shared by both the `.hex` picker (`action_browse_hex`) and the `.bin` picker (`action_browse_app`); `on_select_changed` locks/fills boot-CAN-ID inputs from `DEVICE_CAN_IDS` for KNOWN devices and `_parse_can_id` validates them. All hardware calls run in `@work(thread=True)` workers that call back into `flasher`; no direct USB/serial access.
- **`dfu_config.py`** — encodes the frozen 80-byte v2 DFU config block (`build_config_block()`) written to RA4M1 data flash at `0x40101C00`: magic `0xDF0C0FDF`, version 2, manufacturer/product ASCII strings (≤32 chars each), a per-device boot CAN ID pair (`boot_cmd_id`/`boot_reply_id`, `UNSET_CAN_ID = 0xFFFF` sentinel), and a trailing CRC32 over the first 76 bytes. `DEVICE_CAN_IDS` is the single source of truth mapping known device names to fixed `(boot_cmd_id, boot_reply_id)` pairs; `DEVICE_NAMES` is derived from its keys. `boot_ids_for_device()` looks up a device's fixed pair (`None` for a CUSTOM name). Defines `DfuConfigError`/`InvalidNameError`/`InvalidCanIdError`. Layout/CRC is a frozen contract shared byte-for-byte with the bootloader.
- **`flasher.py`** — UI-agnostic core engine, no Textual dependency. Probe/target: `list_probes()`, `find_esp_prog()`, `detect()` (VID `0x303A`/PID `0x1002` CMSIS-DAP probe, `r7fa4m1ab` core over SWD, halt+read-PC to distinguish blank vs. programmed). `flash()` reset-and-halts then programs a `.hex` via `FileProgrammer` and optionally writes a DFU config block (`_program_config_block()` via `FlashLoader`, enabling the RA4M1 `DFLCTL` data-flash read before verifying). `flash_app()` programs an application `.bin` at `APP_BASE_ADDRESS = 0x4000` (overridable `base_address`) via `FileProgrammer(..., chip_erase="sector")`, sector-erasing only the touched app pages so the bootloader is preserved. `write_dfu_config()` writes the name/CAN-ID block standalone. ESP-Prog-2 probe firmware: `find_probe_firmware()`, `find_probe_serial()`, `download_probe_firmware()` (truststore-backed HTTPS fetch of Espressif's official JTAG image), `flash_probe()` (subprocess esptool, or the `ESPTOOL_SHIM_FLAG` re-exec path for frozen builds). `_find_bundled()` resolves bundled `hex/`/`firmware/` assets from a PyInstaller `_MEIPASS` bundle first, then by walking up from the package/CWD. Backends (`pyocd`, `serial`, `esptool`, `truststore`) are imported lazily inside functions. Defines `FlasherError`/`ProbeNotFoundError`/`FlashFailedError`, `TargetState`, `DetectResult`, `ProbeInfo`, `ProbeSerial`.
