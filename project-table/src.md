**src/** — the `esp_prog2_flasher` package (3.1.0): a UI-agnostic pyOCD/esptool flashing engine, DFU config-block and board-profile encoders, an argparse CLI, and a Textual dashboard TUI that remembers its state between launches.

- **Responsibility:** All runtime code. Flashes the RA4M1, the PSoC 6, SOLO ESP32-S3 boards and the ESP-Prog-2 probe firmware; provisions and reads back node config; offers a headless CLI and a TTSSH-style TUI.
- **Key files:** `esp_prog2_flasher/flasher.py`, `esp_prog2_flasher/cli.py`, `esp_prog2_flasher/app.py`, `esp_prog2_flasher/dfu_config.py`, `esp_prog2_flasher/board_profile.py`, `esp_prog2_flasher/tui/state.py`
- **Relationships:** Uses pyocd, esptool, pyserial, intelhex, truststore, textual, rich, and the `gh` CLI (SOLO bundle fetch only). Bundled assets (`hex/`, `packs/`, `firmware/`) are resolved at runtime by `flasher.py`. Exposes the `esp-prog2-flasher` entry point (`cli.main`), the `flasher.*`, `dfu_config.*` and `board_profile.*` APIs, and `FlasherApp`.

## src/esp_prog2_flasher/

- **Responsibility:** The package: `flasher.py` is the hardware engine (no Textual dependency); `dfu_config.py` and `board_profile.py` encode and decode the frozen on-device blocks; `cli.py` is the headless entry point; `app.py` owns the TUI session.
- **Key files:** `flasher.py`, `cli.py`, `app.py`, `dfu_config.py`, `board_profile.py`
- **Relationships:** Dependency order `dfu_config` ← `board_profile` ← `flasher` ← `cli` / `app`; only `app.py` imports `tui/`.

- **`__init__.py`** — Package marker; `__version__ = "3.1.0"`, shown in the TUI header.
- **`__main__.py`** — `python -m esp_prog2_flasher` calls `cli.main()`; also the script PyInstaller freezes.
- **`dfu_config.py`** — The 80-byte v2 DFU config block (USB manufacturer/product names, optional boot CAN ID pair): `build_config_block`, and `parse_config_block`, which never raises and also accepts a legacy v1 block. Frozen contract with the bootloader. Owns `CONFIG_ADDRESS` and `DEVICE_CAN_IDS`, the single source of truth for known devices (incl. `SOLO ODU Controller` 0x05/0x06, `SOLO IDU Controller` 0x07/0x08); `DEVICE_NAMES` derives from it. Raises `InvalidNameError` / `InvalidCanIdError`.
- **`board_profile.py`** — The 24-byte ESP32-S3 board-profile record (TWAI pins, `Bitrate`, hold-LOW GPIO mask) at cancfg offset 0x50; frozen contract with the Embedded-CAN-Bootloaders firmware.
  - `build_cancfg_image` pads block + record to the 4 KB cancfg image; `parse_profile_record` never raises (invalid or absent → `None`).
  - Owns `SOLO_PROFILES` (SOLO ODU/IDU presets), `DEFAULT_PROFILE_RECORD` (the updater's fallback, mirrored) and `BITRATE_LABELS`.
  - `describe_profile_record` / `describe_read_profile` give the one-line text (`TWAI tx GPIO4 rx GPIO5, 250 kbit/s, hold-LOW mask 0x0`, or "no board profile (updater defaults: …)").
- **`flasher.py`** — UI-agnostic engine; all backends imported lazily.
  - pyOCD over SWD: RA4M1 hex, application `.bin` and DFU config block; PSoC 6 main flash via `psoc6_flash_segments` / `flash_psoc6`; `detect` / `detect_psoc6`.
  - esptool: ESP-Prog-2 firmware (`flash_probe`, `download_probe_firmware`); node config (`provision_node`, `read_node_config` → `NodeConfig(config, profile)` decoded from one cancfg read); SOLO bundles (`load_solo_bundle`, `fetch_solo_bundle` via `gh`, `flash_solo`).
  - Probe-port detection: `SerialPortInfo.is_esp_prog_bridge` (303A:1002, the running bridge) vs `is_download_mode_candidate` (303A:1001 — the ESP-Prog-2 in download mode or a SOLO board). `find_probe_serial()` returns only the bridge and never guesses; `find_download_mode_candidates()` lists the 1001 ports; `list_serial_ports()` lists everything.
  - Owns the `FlasherError` hierarchy (`ProbeNotFoundError`, `FlashFailedError`, `BundleError`), `ESPTOOL_SHIM_FLAG`, bundled-asset lookup (PyInstaller `_MEIPASS` first) and cancfg partition-table parsing.
- **`cli.py`** — argparse entry point; with no flags it launches the TUI (imported lazily). Flags drive `flasher` headlessly, including `--flash-solo`, `--provision-node` and `--read-node-config` (prints the config plus the board profile via `describe_read_profile`); intercepts the hidden esptool shim flag.
  - `--no-state` (TUI only) skips loading and saving remembered state; passed to `app.run`.
  - `--flash-probe` without `--port` uses only the running bridge; with only 303A:1001 candidates it lists them and exits 2, and with no port at all it exits 2 — it never guesses. Node and SOLO flags require `--port`.
  - `--list` reports the running bridge and each download-mode candidate separately.
- **`app.py`** — Textual `FlasherApp`. Owns the session state (`Settings`, detect results, serial port, recents, log, status), command dispatch, and the thread workers that run every flasher call (exclusive `flash` group); never touches hardware directly. Saved state: `state_path` / `no_state` constructor args; `_load_saved_state` applies `state.load_state` + `restore_settings` and restores recents, selection and folds; `_save_state` writes after edits, runs, picks and folds (skipped for `--no-state` or a newer/foreign file; a failure warns once); `_forget_state` handles `/ c`.

## src/esp_prog2_flasher/tui/

- **Responsibility:** TTSSH-style terminal UI: theme, framing widgets, dashboard and run/log/help screens, wizards and their flows, file browser, the `/` command table, the target list, and the saved-state file. Draws state and turns keys into requests; `app.py` runs the jobs.
- **Key files:** `state.py`, `screens.py`, `flows.py`, `wizard.py`, `targets.py`, `browser.py`, `commands.py`
- **Relationships:** Uses `flasher` (constants, `SerialPortInfo` in `flows.py`), `dfu_config`, `board_profile`, textual, rich. Consumed only by `app.py`.

- **`__init__.py`** — Package docstring listing which module owns what; no code.
- **`theme.py`** — TTSSH `Palette` tokens built into dark and light Textual `THEMES`; `theme_name_for_terminal` reads `COLORFGBG`; owns `STATUS_SYMBOLS` (✓ ! ✗ ·).
- **`widgets.py`** — Header, status line, footer hints, the type-to-filter `FilterList` and `DetailsView`, all rendering from one shared `ChromeState`.
- **`screens.py`** — `ChromeScreen` frame, `DashboardScreen` (target tree with fold state, selection details; details hidden below 80 columns), `CommandPopup`, `RunScreen`, `LogScreen`, `HelpScreen`.
- **`wizard.py`** — Step-by-step `WizardScreen` (`TextStep`, `ChoiceStep`, `Confirm`, `WizardSpec`, `Answers`); dismisses with answers only after the last step (and `y` on a confirm).
- **`browser.py`** — Filterable file/folder browser (`BrowseSpec`, `BrowserScreen`) returning an existing `Path` or `None`; `BrowseSpec.recent` shows the picker kind's last picks under `── Recent ──`; `/` offers `.` (this folder) and `t` (type a path).
- **`commands.py`** — The single command table for the popup, the details pane and help: `DASHBOARD_COMMANDS`, `BROWSER_COMMANDS`, `GLOBAL_COMMANDS` (incl. `c` forget saved state), `PRIMARY_ACTIONS`.
- **`targets.py`** — Dashboard data: `TARGET_GROUPS` (RA4M1 and PSoC 6 over SWD; SOLO boards and the ESP-Prog-2 over USB), `Target`, `RecentRun`, `Operation`, `MAX_RECENTS` (10), `MAX_RECENT_FILES` (5 per picker kind), `relative_time`.
- **`flows.py`** — Per-target wizard steps, validation and confirm summaries. Owns `Settings` (incl. `recent_hex` / `recent_bin` / `recent_bundle`); typed jobs `BootFlashJob`, `AppFlashJob`, `Psoc6FlashJob`, `SoloFlashJob`, `SoloProvisionJob`, `SoloReadJob`, `ProbeFlashJob`; `JobFlow` / `EditFlow` builders; `image_browse`, `remember_picked_files` (de-duplicated, capped), `port_label`. Pure: no hardware calls; resolving a flow returns a copy of `Settings`.
- **`state.py`** — Saved TUI state, the feature's only file I/O.
  - `default_state_path()`: `%APPDATA%\esp-prog2-flasher\state.json` on Windows, else `$XDG_CONFIG_HOME` (or `~/.config`) `/esp-prog2-flasher/state.json`. `STATE_VERSION = 1`.
  - JSON: `{version, settings{…}, recent_files{hex, bin, bundle}, recents[{target, operation, detail, ok, message, at}], selected, collapsed}`; boot CAN IDs only for a Custom device; nothing sensitive.
  - `load_state` never raises → `LoadResult(state, problem, overwritable)`; unknown or newer versions are not overwritable; wrong-typed fields keep defaults. `save_state` is atomic (temp file + `os.replace`); `forget_state` deletes the file. `restore_settings` falls back to defaults for vanished paths and drops missing recent files.
