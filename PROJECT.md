`esp-prog2-flasher` — a `uv`-managed Python TUI/CLI for the ESP-Prog-2 debug probe.
It flashes a bootloader to a target board (Renesas RA4M1 / UNO R4 Minima) over SWD
with **pyOCD**, and reflashes the ESP-Prog-2's own ESP32-S3 firmware with **esptool**.

## Architecture Overview

The package is layered so the flashing logic has **no UI dependency**:

- **`flasher.py`** is the engine. It wraps two backends behind plain functions and
  dataclasses: **pyOCD** for the ARM target (detect the ESP-Prog-2 CMSIS-DAP probe
  by VID `0x303A`/PID `0x1002`, examine an `r7fa4m1ab` core over SWD, halt and read
  the PC to distinguish a blank chip from a programmed one, and program a `.hex`
  via `FileProgrammer`), and **esptool** (via subprocess — or a frozen-build
  self-re-exec shim — with progress regex-parsed from stdout) for the ESP-Prog-2's
  own ESP32-S3 firmware, plus **pyserial** port detection and a **truststore**-backed
  download of Espressif's official image. It imports no UI code, and resolves the
  bundled `hex/`/`firmware/` assets from a PyInstaller `_MEIPASS` bundle first,
  then by walking up from the package/CWD.
- **`app.py`** is a **Textual** TUI (`FlasherApp`) that calls `flasher` from
  `@work(thread=True)` workers, marshaling progress/log back to widgets with
  `call_from_thread`. It never touches USB/serial directly.
- **`cli.py`** is the single entry point: bare invocation launches the TUI; flags
  (`--detect`, `--flash`, `--flash-probe`, `--update-probe-fw`, `--list`, …) drive
  `flasher` headlessly. It also intercepts a hidden esptool shim flag used by
  frozen builds.
- **`hex/`, `firmware/`, `tools/`** are bundled data + docs, resolved at runtime by
  `flasher`.
- **Packaging/CI:** `esp-prog2-flasher.spec` + `scripts/build.{ps1,sh}` produce a
  one-file executable via PyInstaller; `.github/workflows/build.yml` builds it on
  Windows/macOS/Linux for every push and attaches the binaries to a GitHub Release
  on `v*` tags.

Two distinct flash paths: **target** (RA4M1 over SWD via pyOCD) and **probe**
(ESP32-S3 over its ROM download port via esptool) — kept separate throughout.
