`esp-prog2-flasher` (v2.2.0) — a `uv`-managed Python TUI/CLI for the ESP-Prog-2 debug probe.
It flashes a bootloader to a Renesas RA4M1 (UNO R4 Minima) over SWD with **pyOCD**, optionally
writes a device config block (custom USB DFU manufacturer/product names plus a per-device
bootloader CAN ID pair) into the target's data flash, can flash an application `.bin` to the
RA4M1 app region (`0x4000`, or `0x8000` for the Embassy bootloader), programs the IDU Radar's
**PSoC 6** (PSoC 62S3 / CY8C6245) with a full bootloader + App1 image over the same SWD link,
and reflashes the ESP-Prog-2's own ESP32-S3 firmware with **esptool**.

## Architecture Overview

The package is layered so the flashing logic has **no UI dependency**:

- **`flasher.py`** is the engine. It wraps **pyOCD** for the ARM targets: detect the ESP-Prog-2
  CMSIS-DAP probe by VID `0x303A`/PID `0x1002`, open a session whose target is chosen per call
  (`_open_session(target_type, use_pack)`), halt/read the PC to tell blank from programmed
  (`_detect_target`, shared by `detect` and `detect_psoc6`).
  - **RA4M1** (`r7fa4m1ab`, resolved offline from the bundled slim RA_DFP pack): reset-and-halt
    then program a `.hex` via `FileProgrammer`, optionally **write a DFU config block** to data
    flash `0x40101C00` via `FlashLoader` (enabling the `DFLCTL` read before verifying), and
    program a raw **application `.bin`** with `flash_app()` at `APP_BASE_ADDRESS = 0x4000`
    using sector erase so the bootloader below is preserved.
  - **PSoC 6** (`cy8c6xx5`, built into pyOCD — no pack): `flash_psoc6()` parses the hex with
    IntelHex and `psoc6_flash_segments()` keeps only main flash (`0x10000000–0x10080000`),
    drops Cypress metadata pseudo-sections (`0x9xxxxxxx`) and refuses anything else (SFLASH,
    eFuse) before touching hardware, then programs via `FlashLoader` and resets.
  - It drives **esptool** (subprocess or frozen-build shim) for the ESP-Prog-2's own ESP32-S3
    firmware, plus **pyserial** port detection and a **truststore**-backed official-image download.
    Backends are imported lazily; bundled `hex/`/`packs/`/`firmware/` assets resolve from a
    PyInstaller `_MEIPASS` bundle first, then by walking up from the package/CWD.
- **`dfu_config.py`** encodes the frozen 80-byte v2 DFU config block — manufacturer/product names
  plus a per-device bootloader CAN ID pair (`0xFFFF` = unset). Its layout and CRC must stay in
  lockstep with the bootloader's `src/boot/dfu_config.*`. `DEVICE_CAN_IDS` is the single source of
  truth mapping known devices to fixed CAN ID pairs; `DEVICE_NAMES` derives from its keys.
- **`app.py`** is a **Textual** TUI (`FlasherApp`) calling `flasher` from thread workers; it never
  touches USB/serial directly. Panels: target (bootloader hex, manufacturer/device rows, "Custom…"
  device, boot-CAN-ID inputs, Detect/Flash target), ESP-Prog-2 firmware, "Application (RA4M1 over
  SWD)" (app `.bin`, Embassy `0x8000` option), and "PSoC 6 (IDU Radar over SWD)" (hex picker
  defaulting to the bundled image, key `6`, not gated on RA4M1 detect). `FilePickerScreen` is
  suffix-generalized and shared by all pickers.
- **`cli.py`** is the single entry point: bare invocation launches the TUI; flags (`--detect`
  [`--psoc6`], `--flash`, `--flash-psoc6`, `--flash-app`, `--app-address`, `--flash-probe`,
  `--update-probe-fw`, `--hex`, `--freq`, `--manufacturer`, `--product`, `--boot-cmd-id`,
  `--boot-reply-id`, …) drive `flasher` headlessly. It also intercepts a hidden esptool shim flag
  used by frozen builds.
- **`hex/`, `packs/`, `firmware/`, `tools/`** are bundled data + docs resolved at runtime by
  `flasher`; **`docs/images/`** holds README screenshots.
- **Packaging/CI:** `esp-prog2-flasher.spec` + `scripts/build.{ps1,sh}` produce a one-file
  executable via PyInstaller; `scripts/install.{ps1,sh}` fetch a released binary onto PATH;
  `scripts/run-termux.sh` runs from source on Termux/Android (arm64); `.github/workflows/build.yml`
  builds on Windows/macOS/Linux and publishes a GitHub Release on `v*` tags.

Two distinct flash paths: **target** (SWD via pyOCD — RA4M1 bootloader `.hex`/application `.bin`,
and the PSoC 6 full image) and **probe** (ESP32-S3 over its ROM download port via esptool) — kept
separate throughout.
